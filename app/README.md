# Majestic Assistant — WPF-оверлей

Этапы 1-4: скелет оверлея + поиск по базе знаний через локальную модель (Ollama) + иконка в трее
и сохранение настроек между запусками. Написан на macOS, собирать и запускать нужно на Windows
(WPF компилируется только под Windows) — я не могу проверить это сам, поэтому ниже подробная
инструкция и список того, что стоит проверить в первую очередь.

## Требования

- Windows 10/11
- [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0)
- Visual Studio 2022 (любая редакция, включая Community) **или** VS Code с расширением C Dev Kit —
  оба варианта одинаково подходят, ниже команды для обоих.
- [Ollama](https://ollama.com) — для локальной модели. Установи, затем в терминале:
  ```
  ollama pull nomic-embed-text
  ollama pull qwen2.5:7b
  ```
  `nomic-embed-text` — маленькая модель для поиска (эмбеддинги), `qwen2.5:7b` — модель, которая
  формулирует сам ответ. Если 7b слишком тяжёлая для твоей видеокарты — замени на `qwen2.5:3b`
  или `llama3.1:8b` (значения задаются в `Services/Rag/RagService.cs`, свойства `EmbedModel` /
  `ChatModel`). Ollama должна быть запущена (просто установленное приложение уже держит фоновый
  сервис на `localhost:11434` — отдельно ничего запускать не нужно).

## Сборка и запуск

### Через терминал (PowerShell/cmd)

```
cd app/MajesticAssistant
dotnet build
dotnet run
```

### Через Visual Studio

Открой `app/MajesticAssistant/MajesticAssistant.csproj` (или создай `.sln` через
`dotnet new sln` + `dotnet sln add MajesticAssistant.csproj`, если нужен файл решения) и нажми
F5.

## Что должно произойти при запуске

Приложение стартует **без видимого окна** — это ожидаемо, оверлей скрыт до первого нажатия
хоткея (см. `App.xaml.cs`). Параллельно в фоне сразу начинается индексация базы знаний
(`data/kb/`) — при первом запуске это может занять пару минут (эмбеддинг нескольких сотен
фрагментов через Ollama), при следующих запусках почти мгновенно благодаря кэшу
(`cache/embeddings.json` рядом с exe).

## Проверка (раз я не могу сделать это сам)

1. Запусти приложение — окна быть не должно, но процесс `MajesticAssistant.exe` должен появиться
   в диспетчере задач.
2. Нажми **Alt+Space** — должна появиться полупрозрачная тёмно-синяя панель в правом верхнем углу
   экрана с анимацией появления. В поле ответа сначала должно быть «Загружаю базу знаний…», затем
   «Индексирую базу знаний… N/M» (при первом запуске), в конце — «Готов отвечать на вопросы по
   правилам сервера.».
   - Если вместо этого сразу видишь «Ollama не запущена...» — проверь, что Ollama установлена и
     запущена (иконка в трее Windows), и что модели из `ollama pull` выше действительно скачаны
     (`ollama list` покажет список).
3. Кликни в любое приложение позади (или на рабочий стол) — панель должна скрыться сама
   (потеря фокуса).
4. Снова Alt+Space → дождись «Готов отвечать…» → напиши вопрос по правилам сервера
   (например: *«Какой штраф за превышение скорости на 50 км/ч?»* или *«Что будет за DM?»*) →
   Enter — ответ должен начать появляться постепенно (стриминг), со ссылкой на источник
   в конце вида `[Источник: ...]`.
5. Задай вопрос **не по теме сервера** (например про погоду) — ассистент должен честно сказать,
   что не нашёл ничего подходящего в базе знаний, а не выдумывать ответ.
6. Пока идёт генерация ответа — сразу задай новый вопрос. Старый ответ должен оборваться,
   должен начать печататься ответ на новый вопрос (без ошибок/краша).
7. Нажми **Escape** — панель скрывается.
8. Попробуй зажать левую кнопку мыши на панели (не на кнопках/поле ввода) и потащить —
   панель должна переместиться.
9. Проверь Alt+Tab — окна оверлея в списке быть не должно.
10. В системном трее (стрелочка рядом с часами) должна появиться иконка ассистента (тёмно-синий
    кружок с белой «M» и красной точкой) с подсказкой «Majestic Assistant — Alt+Space» при наведении.
11. Двойной клик левой кнопкой по иконке в трее — должен показать/скрыть панель, так же как
    Alt+Space.
12. Правый клик по иконке в трее — должно появиться меню «Показать / скрыть» и «Выход». Пункт
    «Выход» должен полностью закрыть процесс (проверь по диспетчеру задач) и убрать иконку из трея.
13. Подвигай панель (зажми и потащи за пустое место, не за кнопки), закрой приложение через
    «Выход» и запусти заново — панель должна появиться там же, где её оставили, а не в правом
    верхнем углу по умолчанию.

Если что-то из этого не работает — пришли мне, что именно (и что написано в поле ответа, если
там ошибка), и я поправлю код.

### Смена модели без правки кода

Рядом с exe при первом выходе из приложения появится `settings.json`. Чтобы сменить модель
эмбеддингов/ответа без пересборки — закрой ассистента, открой `settings.json` и впиши нужные
названия:

```json
{
  "windowLeft": 1500.0,
  "windowTop": 28.0,
  "embedModel": "nomic-embed-text",
  "chatModel": "qwen2.5:3b"
}
```

`embedModel`/`chatModel` можно оставить `null` — тогда используются значения по умолчанию из
`RagService.cs`. `windowLeft`/`windowTop` перезаписываются автоматически при каждом выходе —
трогать их вручную не обязательно.

## Структура проекта

```
MajesticAssistant/
├── MajesticAssistant.csproj   — включает копирование data/kb → bin/.../kb при сборке
├── app.manifest                — per-monitor DPI awareness
├── App.xaml(.cs)                — точка входа, окно создаётся скрытым
├── MainWindow.xaml(.cs)         — сама панель оверлея, связывает UI с RagService
├── Models/
│   ├── KnowledgeChunk.cs        — один фрагмент базы знаний (текст + откуда он)
│   └── AppSettings.cs           — что сохраняется между запусками (позиция окна, модели)
├── Theme/
│   └── DarkGlassTheme.xaml      — токены дизайна (скилл dark-glass-ui): цвета, стили панели/полей/кнопок
└── Services/
    ├── HotkeyService.cs         — глобальный хоткей Alt+Space через RegisterHotKey (работает поверх игры)
    ├── WindowStyleHelper.cs     — прячет окно из Alt+Tab (WS_EX_TOOLWINDOW)
    ├── TrayIconService.cs       — иконка в системном трее: показать/скрыть, выход
    ├── SettingsService.cs       — читает/пишет settings.json рядом с exe
    └── Rag/
        ├── MarkdownChunker.cs   — режет .md файлы базы знаний на фрагменты по заголовкам
        ├── OllamaClient.cs      — HTTP-клиент к локальной Ollama (эмбеддинги + генерация со стримингом)
        ├── EmbeddingIndex.cs    — векторный поиск (косинусное сходство) + JSON-кэш эмбеддингов
        └── RagService.cs        — склеивает всё: индексация при старте, ответ на вопрос
```

## Как это работает (Этап 3)

1. При старте `MarkdownChunker` читает все `.md` из `data/kb/` и режет их на фрагменты по
   заголовкам (`## Глава`, `### Раздел` и т.д.), не разрывая длинные разделы посреди абзаца.
2. Каждый фрагмент превращается в вектор через Ollama (`nomic-embed-text`); векторы кэшируются
   на диске по хэшу содержимого, так что при повторном запуске без изменений в базе знаний
   переиндексация не нужна.
3. Когда игрок задаёт вопрос, он тоже превращается в вектор, и через косинусное сходство
   находятся 6 самых релевантных фрагментов.
4. Эти фрагменты вместе с вопросом отправляются в модель (`qwen2.5:7b`) с явной инструкцией
   отвечать только на их основе и не выдумывать — ответ стримится в панель по мере генерации.

## Что НЕ сделано сознательно

- Квиз (генерация вопросов из базы знаний для самопроверки) — временно исключён из плана, вкладка
  в UI убрана. Может вернуться отдельным обновлением позже.
- Хоткей (Alt+Space) зашит в код, в `settings.json`/UI не вынесен — как и выбор модели, менять
  можно только вручную (модели — через `settings.json`, хоткей — через `HotkeyService.Register`
  в `MainWindow.xaml.cs`).
- Кэш эмбеддингов, база знаний и `settings.json` лежат рядом с exe в папке сборки — если
  планируется устанавливать приложение через инсталлятор в `Program Files`, это стоит перенести в
  `%LOCALAPPDATA%` (папка сборки может быть недоступна для записи).
